# Daily loop services

Services only; no scene, Game UI, inventory, save model or package manifest was edited. The four approved B concepts were inspected: calendar with completed/available cells, a compact claim sheet, 3-win bonus and gentle reset, and a pre-permission opt-in sheet. Gift amounts come from the server table, rather than the illustrative art.

## Composition and UI API

Create `DailyServices(canonicalPlayerId, ILocalNotifications)` after `Account.Link()` has resolved canonical ownership. Retain one instance per account, and recreate after account switch, deletion, or cloud restore. The iOS implementation is `IosLocalNotifications` in the optional nested assembly. Services run on the Unity main thread, except puzzle construction. No automatic boot creates competing account/service instances. Subscribe `Context.Changed` to persist/cloud backup requests, or the individual service `Changed` events to redraw; unsubscribe UI handlers on screen disposal.

- `Puzzle.CanPlay`, `PrepareAsync()`, `TryGetPrepared(out DailyPuzzle)`, `Start(puzzle)`, `Complete(puzzle, won)`, `RetryRewards()`, `StateFor("yyyy-MM-dd")`, `Streak`, `HasFreeze`, `MilestoneReward(streak)`, `RewardGranted(day)`.
- `Gift.CanClaim`, `NextAt` (UTC), `RewardFor(day)`, `await Claim()` (false when already claimed/busy), `Claimed(DailyReward)`, `Changed`. Disable Collect during request. On failure keep the sheet open and offer retry; never grant locally. RewardFor is preview only; the wallet response owns actual balances.
- `Wins.Count`, `BonusReady`, `OnLevelStart(attemptUuid) -> LevelBonus`, `OnContinue(attemptUuid)`, `OnLevelEnd(attemptUuid, StreakEnd, firstTry)`, `Changed`, `GentleReset`.
- `Notifications.ShouldOfferOptIn`, `OfferShown()`, `ContinueOptIn()`, `SetEnabled(bool)`, `TrackOpen()`, `Changed`. Only the opt-in sheet Continue calls ContinueOptIn. Not now just dismisses. OfferShown records the weekly cooldown before presentation. OS permission is requested once; after denial, Settings must guide the player to iOS settings. All notification/sheet strings are in `DailyStrings.English` for localisation.
- `DailyServices.OnAppOpen(livesFullAtUtc)` counts one foreground session, tracks opens and replaces pending notifications. Call `Reschedule(livesFullAtUtc)` after lives change, daily completion, opt-in or settings change. Call `Puzzle.RetryRewards()` after the telemetry queue has flushed and connectivity returns; surface failure without blocking Home.
- `Wallet.WalletChanged(JObject)` contains the authoritative response. Forward to the existing store wallet adapter/refresh path. Do not add daily amounts to local gold/booster/lives counters. The current backend rejects utc_day: apply the backend spec before enabling claims.

## Exact UI integration hooks for the parent

`Orcub.Runtime` contains both Core and Game; it cannot reference Daily (Daily references Runtime). Follow the existing ClientGateway pattern: the parent adds SDK-free delegate fields to `Game/ClientGateway.cs` and the composition root binds them to these services. Use Core.LevelData/System types and JSON view models across that boundary; never add a circular asmdef reference. The following are the required call sites and payloads:

1. Loader/account composition: after canonical account link/restore, construct DailyServices. Bind gateway callbacks for daily prepare (`Func<Task<LevelData>>`, retain its DailyPuzzle in the binding), daily state/claim, win start (`Func<string,int>` cast LevelBonus), continue, end, and notification opt-in. Forward service Changed to a gateway invalidation event. Preserve the current account ID for the lifetime of each in-flight operation; discard old-account UI results.
2. `TopBar.Build`: calendar button invokes the daily screen navigation callback. Badge uses CanPlay. No saga level index is repurposed. Refresh on Changed and foreground/UTC rollover. At local midnight rebuild the calendar labels/month and 7-day row.
3. `HomeScreen`: gift button opens the compact sheet. Bind Collect to await Gift.Claim; close only on true; bind NextAt countdown and Claimed/Changed. Show opt-in after the third foreground session or first daily completion if ShouldOfferOptIn; call OfferShown immediately before showing, Continue -> await ContinueOptIn then Reschedule, Not now -> dismiss. Never call permission in Awake/Start/session open.
4. Daily screen: enumerate seven days/month cells with StateFor; Upcoming disables play. Today Play awaits PrepareAsync with existing loader; discard if navigation changed or returned Day != Context.Today. Call Puzzle.Start only when the board is actually entering. Board uses returned LevelData directly with LevelRules.For; skip Adaptive selection and saga progression/stars. A daily loss/quit calls Complete(puzzle,false); a daily win calls await Complete(puzzle,true), then reschedule and evaluate opt-in. Show completion immediately even if reward is pending; retry grant separately. Midnight permits yesterday's already-started board to finish, but forbids opening it anew. Never publish a daily result as saga level_end.
5. `BoardView`: after the saga board is ready, create one fresh attempt UUID and call Wins.OnLevelStart before enabling input. Apply returned Hint/Undo/Unclamp as a free pre-placed **attempt-local** bonus; do not call BoosterInventory.Add/Use or wallet spend. Hold the bonus token on that attempt; repeated start for the same UUID returns the same token, so BoardView must apply it once. New attempts get new UUIDs. Terminal win -> OnLevelEnd(id,Win,firstTry); terminal accepted loss -> Loss; confirmed home/back/abandon -> Quit. Persisted active attempts abandoned on relaunch are closed as Quit before starting a fresh UUID. Daily boards do not invoke the saga win-streak hooks.
6. Continue offer is not a terminal loss: leave the attempt open while the player chooses. On successful ad/gold continue call OnContinue(id) before resuming. A continued win preserves the prior streak, with no increment. Only an actual accepted loss/quit resets; reset copy uses DailyStrings reset text. At three wins the next start consumes one rotating Hint/Undo/Unclamp bonus and starts a new 0/3 cycle.

## Dates, difficulty and rewards

Completion keys are UTC yyyy-MM-dd worldwide. Calendar labels/month/7-day row roll at **local midnight for display only**; map a cell to its explicit UTC key, and label the UTC reset countdown. Travel/DST do not mint an extra puzzle or claim. The observed UTC high-water mark blocks clock rollback locally; deterministic SHA256 grant UUIDs plus server `(player,reason,date)` uniqueness protect repeats after crashes/reinstall. The server clock is authoritative; a forward-skewed device may temporarily block itself and must refresh from server time rather than locally award.

Daily v1 derives an FNV seed from `orcub/daily/v1/<UTC date>` and uses the public InfiniteGenerator.Generate API with a frozen six-ring maximum, non-boss curve and PCG choices. A daily PCG palette permutation/reflection preserves mechanics; VerifyWitness revalidates the transformed result. IDs are negative date ordinals, gen_version has a daily namespace and no LevelLibrary/saga cache/progression is touched. The infinite library API only accepts saga indices; using PrepareAsync(sagaIndex) for daily would share cache/config. This service instead queues the same public generator asynchronously and offers its own readiness API. Daily v1 depends on infinite algorithm v1; freeze that implementation or bump the globally scheduled daily version before future generator changes. No adaptive/RC/player skill enters this board.

Streak: consecutive UTC completions; exactly one skipped day consumes the single freeze without adding a completed cell or increment for the skipped day. Longer gaps reset to one on the next completion. One freeze is earned on first reaching seven, capacity one, never farmed by resetting. Milestones on the current streak: 3 = 30 gold; 7 = 1 Hint; 14 = 2 Undo; 30 = 100 gold. Reaching seven also earns the freeze. Backend computes/applies rewards, never trusts the local streak. Gift rotation by UTC day ordinal since 1970 modulo 3: 20 gold, 1 Hint, 30 minutes unlimited lives. Unlimited duration begins on server grant, not sheet open. Failed puzzle grants remain pending; gifts retry their same date key. No local inventory is credited.

## Save integration

`DailySaveSection` is serializable v1; `DailyPersistence.Capture/Restore` is the cloud section codec; Load/Save stores a synchronous account-scoped PlayerPrefs checkpoint. Add `daily` to SaveSnapshot.Capture using JObject.Parse(Capture(state)); after accepted Apply restore the section, checkpoint it and recreate services. On revision conflict take server mutable daily state (wins/bonus/preferences), union Completed and PendingPuzzleGrants, max HighestUtcDay/LastGiftDay and preserve any unacknowledged local completion pending grant. Reconcile puzzle streak/freeze against server daily claim history rather than summing; pending grants' deterministic keys make their replay safe. Do not run old service instances after restore. Backend SaveData must accept/validate this section before upload (see backend spec). Cloud section is backup, never economy authority.

## Notification package hook (outside this task's write scope)

Parent adds `com.unity.mobile.notifications: 2.4.3` to Packages/manifest.json and resolves lock. The nested iOS asmdef version define then enables the typed adapter. Disable **Request Authorization on App Launch** and **Enable Push Notifications** in Mobile Notification settings; never request APNs registration. AuthorizationRequest uses `registerForRemoteNotifications:false`. Documentation: https://docs.unity3d.com/Packages/com.unity.mobile.notifications@2.4/manual/iOS.html . Without the package the optional adapter is excluded; no fabricated permission/scheduling succeeds. Parent composition must supply a fake only for editor tests, not production.

Quiet hours are 22:00 inclusive–08:00 exclusive in TimeZoneInfo.Local. Civil 08:00 is recalculated across DST. There is only one pending notification total, choosing earliest eligible lives-full/daily-ready/streak-risk candidate; delivery reserves its local date. App open cancels/replaces pending IDs, infers an already elapsed schedule as delivered, and persists cap state. Risk reminders deferred past the UTC deadline are discarded. OS denial or opt-out cancels pending. Device timezone changes while the app stays closed require a device check; iOS elapsed-time delivery cannot recalculate quiet hours without app execution. iOS may delay delivery due to Focus; scheduled time is not delivery proof.

Telemetry uses ClientGateway.Track -> existing durable queue. daily_puzzle_start/end, daily_gift_claim, win_streak_change, notif_optin, notif_open use only metric_ numeric/bool fields, compatible with the backend future-kind allowlist. No date strings/identifiers enter telemetry; metric_day is UTC day ordinal. Local notification IDs are kept locally. Do not treat queue acceptance as gameplay attestation.
